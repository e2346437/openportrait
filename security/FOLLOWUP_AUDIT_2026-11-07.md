# OpenPortrait security follow-up

Reviewed main at `a067a0543afcd51a79a13d79ec4be2173809de1c`. This was a source review focused on request authentication and proxy trust, gallery access, extension loading, and the CI and release path. The existing security registry remains the record of earlier dynamic results. This review used repository source and synthetic gate fixtures. It did not exercise live deployments, run Docker/ZAP or perform a fresh history or dependency scan.

| Priority | Evidence | Recommendation |
| --- | --- | --- |
| High | `security/scripts/gate.mjs` previously allowed enforcement to pass with absent scanner output. `scan.sh` discarded scanner failure status, and the image job neither installed Semgrep nor shared evidence with the static job. | This branch requires report evidence in enforce mode, propagates scanner failures, redacts Gitleaks output, and supplies Semgrep and history to the image job. Exercise the full workflow before relying on it for a release. |
| High | `.github/workflows/image.yml` publishes `latest` from main and version tags independently of security checks. The security workflow’s release event runs after publication. | Build a candidate once, enforce checks against that digest, and promote that exact digest only after the gate succeeds. Require successful checks and review for main and restrict version tag creation. |
| Medium | Release and scanner inputs include movable action tags, container tags and a floating Semgrep dependency. The image publish job grants package write permission. | Pin Actions to verified full commit SHAs and scanner images to verified digests. Use a reviewed, locked Semgrep version and give only the promotion job package write permission. |
| Medium | HTTPS decisions are split between `app.ts`, `routes/auth.ts`, `routes/client-gallery.ts`, and `routes/master.ts`. Their treatment of forwarded headers differs from the trusted-socket check used for rate limits. | Define one trusted-proxy HTTPS policy for HSTS and every session or gallery cookie. Verify direct LAN HTTP, trusted tunnel HTTPS, an untrusted direct request, and a separate trusted reverse proxy before rollout. |
| Medium | `extensions.ts` loads executable add-ons in the core process. The loader is an administrative trust boundary. | Restrict write access to the extension directory, require verified bundles for managed installs, and keep studio volumes and service credentials isolated per deployment. |
| Follow-up | The earlier registry still lists SEC-014 for image components and SEC-016 for session controls. Current source includes TOTP code, so the earlier second-factor description needs an end-to-end retest. | Scan the published image digest and retest enrollment, recovery, session expiration, and idle timeout before changing either registry entry. |

The new Node tests cover a clean evidence set, absent and malformed evidence, and a positive finding. They run in the existing Security workflow. Local command: `node --test security/tests/gate.test.mjs`.
